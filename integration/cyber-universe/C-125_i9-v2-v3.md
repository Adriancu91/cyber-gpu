# Pentru sesiunea OS — C-125: o variantă nouă de I9 (V2 + V3), oprită implicit (cyber-gpu `78704e5` sau mai nou)

Sesiunea Cyber-GPU 103, 16 noiembrie 2026. Context: `os-302` (16 nov, workstation) — I8 și golden trec, **I9 pică la `PROMOTE_CTX` virtual cu `0x57`
`NV_ERR_OBJECT_NOT_FOUND`**. Adrian a aprobat (C-125) două încercări, **doar în SIMULARE**; pe placă **doar** în fereastra cu el, odată cu `gpu lant`.
Analiza: `docs/os-302_ANALIZA_I9.md`. Nimic nu e testat pe placă.

## 1. Fără nicio schimbare în OS: nimic nu se schimbă

Interfața publică e neschimbată (doar adăugări). `open_work_channel_cleared` trimite exact aceleași mesaje ca în `os-302` (testul
`c125_off_sends_exactly_what_os302_sent`). Legarea la `78704e5` fără alt cod = același comportament.

## 2. Opțiunea nouă (propunere): `gpu lant --i9 c125` — implicit OPRITĂ

Noul în cyber-gpu: `nvidia_ga104::gsp::user_space::{I9Options, I9Report, CtxInfoAnswer, PrivilegedMemory, open_work_channel_with, journal_rows}`,
`nvidia_ga104::mmu::{encode_pte_privileged, GpuMemory::map_privileged}`, `gsp::rmapi::{CtxBufferInfo, ctx_buffer_info_request, parse_ctx_buffer_info,
cmd::GR_GET_CTX_BUFFER_INFO}`. `GpuMemory<W>` implementează deja `PrivilegedMemory`.

- **V2:** bufferele de context MAIN/PM/PATCH ale canalului de lucru sunt mapate cu bitul `PRIVILEGE` (bitul 5 din PTE), ca nouveau. Doar alte valori în
  tabelele de pagini pe care le scriem deja (aceleași pagini, alt bit); niciun registru nou.
- **V3:** înainte de promovare, un mesaj RM în plus, **doar citire**: `GR_GET_CTX_BUFFER_INFO` (pe subdispozitiv, pentru canalul nostru). Răspunsul (sau
  refuzul, cu numele codului) se scrie în jurnal; **un refuz nu oprește lanțul**. Atenție: în driverul NVIDIA comanda e servită de RM-ul de pe CPU
  (`subdeviceCtrlCmdKGrGetCtxBufferInfo`, fără `ROUTE_TO_PHYSICAL`), deci e posibil ca GSP-RM să răspundă `NOT_SUPPORTED` — și asta e o informație.

În `kernel/src/drivers/gpu_golden.rs`, `channel_step` (schița; `opts` vine din linia de comandă, implicit `I9Options::OS_302`):

```rust
use nvidia_ga104::gsp::user_space::{self, I9Options, I9Report};

let mut rep = I9Report::default();
let r = {
    let mut t = OsRm { /* ca acum */ };
    (|| {
        let u = user_space::open_user_space(&mut t, gi.next_handle(), mem.root())?;
        let cg = user_space::open_compute_group(&mut t, &u)?;
        let w = user_space::open_work_channel_with(&mut t, &mut *mem, &u, &cg, gi, opts, &mut rep)?;
        user_space::query_gr_info(&mut t, &u)?.check_sm86()?;
        Ok::<_, GpuError>((u, w))
    })()
}
.and_then(|x| flush(vbar, journal, permit, zone, pending, vram_words).map(|_| x));
// Jurnalul e liber din nou (t s-a terminat): raportul ajunge pe stick ȘI când I9 pică (cazul os-302).
if opts != I9Options::OS_302 {
    rep.journal(journal);
}
```

Rândurile din jurnal (toate încep cu `i9 `): `i9 c125 optiuni (b0 V2 priv, b1 V3 lista) = 3`, apoi `i9 v3 GR_GET_CTX_BUFFER_INFO stare = …` (+ `text i9 v3 refuz
= "NV_ERR_…"` la refuz) sau lista (`i9 v3 buf tip/marime/aliniere/pagina/aperture/kind/…`), apoi bufferele noastre (`i9 ctx buf id/va hi/va lo/marime/
privilegiat`, cu `in lista RM` și `marime = RM` când lista există).
